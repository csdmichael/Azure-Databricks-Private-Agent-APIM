# Caldova Fabric APIM stack (Terraform)

This root module adds two delegated OAuth REST APIs and two generated MCP APIs to the existing `config.apim` service. It also creates or reuses the Caldova-side `privatelink.azurewebsites.net` zone, writes broker and broker SCM A records, and links the existing APIM VNet.

The module reads `../../config/deployment.json` by default. Both `azurerm` and `azapi` are explicitly scoped to `config.apim.tenantId` and `config.apim.subscriptionId`; APIM preview resources use API version `2024-06-01-preview` through AzAPI. The APIM service and VNet are referenced, never created.

## Security contract

- The REST and MCP APIs do not require APIM subscription keys. The inbound policy also removes both subscription-key forms before forwarding.
- APIM validates a signed, unexpired delegated token from the Fabric resource tenant. It requires the configured audience, `tid`, delegated `scp`, connector `azp`, and Fabric guest `oid`; app tokens are rejected.
- APIM saves the user bearer assertion, replaces `Authorization` with a system-assigned managed-identity token for `api://<broker_audience>`, and forwards only to the fixed private broker origin.
- The broker must independently validate the managed-identity caller token, APIM principal ID, caller tenant, audience, and configured application role before accepting `x-user-assertion`.
- Per-user throttling uses the verified `oid`. Correlation IDs are generated by APIM. Responses are marked `no-store`; this stack defines no cache policies.
- Optional Application Insights diagnostics record zero request and response body bytes and no headers. Verify any service-wide APIM diagnostic also has frontend response-body logging set to zero, because global diagnostics are outside this module.

No secret variable, resource, or output is defined. Client IDs, object IDs, role names, hostnames, and private IPs are configuration, not credentials.

## Inputs and guardrails

Create `main.tfvars.json` from `main.tfvars.json.example` and replace every `REPLACE-*` value. Variable validation and `terraform_data.guardrails` stop planning or deployment when generated IDs, connector or guest allowlists, the broker URL, or the broker private endpoint IP are empty or malformed. The broker URL must resolve to the app named by `config.broker.appName`.

Set `application_insights_name` only when that component already exists in the Caldova subscription. Leave it null or empty to omit the logger and all four API diagnostics. Set its resource group only when it differs from `config.apim.resourceGroup`.

The default creates `privatelink.azurewebsites.net` in the APIM resource group. To reuse an existing zone, set `create_private_dns_zone` to `false`; set `private_dns_zone_resource_group_name` only when the zone is in another Caldova resource group. Import records or the VNet link before apply if resources with the generated names already exist.

## Validate and preview

Authenticate to the APIM tenant before Terraform reads the existing service:

```powershell
az login --tenant 12a4b86b-e64c-43f9-af05-d9130a72dfd2
az account set --subscription cf824570-a8ba-497a-a184-0a52f1830aa9
terraform -chdir=fabric/terraform/apim fmt -check
terraform -chdir=fabric/terraform/apim init -backend=false
terraform -chdir=fabric/terraform/apim validate
terraform -chdir=fabric/terraform/apim plan -var-file=main.tfvars.json
```

Apply only after the APIM system-assigned identity has the configured broker application role and the broker has the matching `APIM_PRINCIPAL_ID`, audience, role, connector IDs, and Fabric guest IDs.

## Cross-tenant networking

This module intentionally does not create cross-tenant VNet peering. Create the APIM-to-broker peering in the Caldova tenant stage and the broker-to-APIM peering in the Fabric tenant stage. Both stages must use the corresponding remote VNet resource ID and enable virtual-network access; apply any required forwarded-traffic settings there. DNS alone does not provide network reachability.
